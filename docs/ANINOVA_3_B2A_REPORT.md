# AniNova 3.0 — B2-A: Core Web Redesign (первая группа миграции)

Оболочка, навигация, главная, каталог аниме, страница аниме и расписание переведены на Nova Minimal
в изолированном preview. Functional behavior сохранён: те же данные, те же URL, тот же плеер.

| Параметр | Значение |
|---|---|
| База | `design/aninova-3-b1-e1-public-metadata-guard-2026-11` @ `20070b13678df9f8bf0b3f88b10e268ee9ba9b64` |
| Ветка | `design/aninova-3-b2-a-core-web-2026-11` |
| Worktree | `D:/ПРОЕКТ AniNova/anistream-b1e1` |
| `main` в origin | `5d983d555eacf956a952e647579738dbc44a2ce5` (не изменялся) |
| Production | не затрагивался: ни деплоя, ни миграций, ни Supabase/Redis/Vercel |

Спецификация: `AniNova_Master_Specification_v1.0`, этап **B2** (web redesign foundation and page
migration), группа 1–2. Дизайн-система — Nova Minimal из B1-B, тёмная тема как зафиксированное
решение владельца.

## 1. Что сделано по шагам

### 1.1. Shell, навигация, футер

Единый источник правды для разделов — `lib/aninova3/nav.ts` (`A3_NAV`, `isA3NavActive`). Раньше
список пунктов дублировался в `A3Header` и `A3MobileNav`, и активные состояния считались по-разному.

- **Шапка:** Главная · Каталог · Расписание · Comics · Профиль. Страница произведения и серия
  подсвечивают «Каталог» (через `also`), расписание и комиксы не пересекаются по префиксу.
- **Мобильная навигация:** те же 5 разделов; сетка больше не зашита в 4 колонки
  (`grid-auto-flow: column`), поэтому пятый пункт не ломает раскладку на 360 px.
- **Футер:** повторяет разделы (включая расписание), аккаунт и переход на текущий сайт; текст
  прототипа обновлён с B1-B на B2-A.
- **Состояния:** `app/preview/aninova-3/error.tsx` (спокойный экран с «Повторить»/«В каталог»),
  `not-found.tsx` (404 внутри preview с навигацией), `catalog/loading.tsx` и `schedule/loading.tsx`
  (skeleton без клиентского JS).
- Границы загрузки поставлены **точечно**, а не на весь `/preview/aninova-3`: как только сегмент
  начинает стримить оболочку, `notFound()` уже не может вернуть 404. Для страниц, где 404 —
  нормальный сценарий (произведение, серия, читалка), границы загрузки нет намеренно — статус
  остался 404, это проверено регрессией.

### 1.2. Главная

- Афиша (`A3Hero`) сохранена: широкий кадр, скрим, «Выбор редакции», один основной CTA «Смотреть»
  и «Подробнее».
- Новый блок **«Сегодня в эфире»** — реальный день из `getDaySchedule(0)` (то же расписание, что на
  `/schedule`): время МСК, постер, название, номер серии, переход на страницу произведения и на
  серию, ссылка «Всё расписание».
- Сохранены: «Продолжить просмотр» (локальная история `lib/library`, без моков), «Сейчас
  популярно», «Новинки», «Фильмы», «Анонсы», тизер Comics с честной пометкой демо.
- Демо-контент не смешивается с реальным; фиктивных произведений и пользовательских данных нет.

### 1.3. Каталог аниме

Интерфейс подключён к существующему серверному каталогу без клиентской фильтрации:

- поиск (`?q=`) — GET-форма, серверный `filterCatalog`;
- фильтры в адресе: жанр (`genre`, мультизначения), тип, статус, длина, десятилетия годов;
- сортировки `pop | score | new | az` (существующие ключи и семантика `sortTitles`);
- вид `list | grid` (`?view=grid`), пагинация `?page=`;
- активные фильтры с отдельным снятием и «Сбросить всё», пустое состояние с возвратом в каталог;
- совместимость ссылок: `a3CatalogHref` сохраняет все параметры при любом изменении.

Поведение не менялось — только проверено регрессией и не сломано миграцией.

### 1.4. Страница аниме

- Хлебные крошки «Каталог / Название» (раньше их не было).
- Постер, название, оригинальное название, рейтинг, статус, число серий, длительность, жанры —
  реальные поля каталога.
- Список серий с раскрытием остальных (`details`), ссылки ведут в существующий сценарий просмотра
  (`/anime/<slug>/<n>` → кинозал `A3Theatre` + существующий `PlayerShell`), плеер и провайдеры
  не тронуты.
- Новый блок **«Источники и просмотр»**: честно объясняет, что наличие потока и перевода
  проверяется на странице серии. Список провайдеров на странице тайтла намеренно **не** выводится:
  по названию произведения нельзя утверждать, что источник доступен.
- «Франшиза» — существующая логика `lib/franchise.watchOrder` (BFS по связям), отдельная лента.
- «Похожее», досье (`Тип`, `Статус`, `Год`, `Серии`, `Студия`, `Длительность`, `Первоисточник`,
  `Рейтинг`), персонажи — сохранены.
- Пустые состояния: нет описания → «Описание пока не заполнено», нет серий → «Серии ещё не вышли»
  и CTA «Скоро» вместо «Смотреть».

### 1.5. Расписание (новый preview-маршрут)

`/preview/aninova-3/schedule` — новый маршрут; production `/schedule` не изменялся.

- Данные: `getWeekSchedule()` из `lib/schedule` — таблица `airing_schedule` воркера, а до её
  заполнения — реальный график каталога (`airing`). Демо-недели нет.
- Бизнес-логика не менялась: окно −2…+8 дней, границы недели, МСК (`Europe/Moscow`, UTC+3 без
  перехода на летнее), группировка по дню — всё в `lib/schedule-core`.
- Переключатель дней: `?day=0…6`, рядом с днём — дата и число показов; сегодняшний день помечен
  точкой и подписью, мусор в `?day=` не ломает страницу (показывается текущий день).
- Строка эфира: время МСК (`<time datetime>`), постер, название, «Серия N», статус
  «вышла / сейчас / ожидается» (подпись, а не только цвет), кнопка «Смотреть».
- Пустой день — нормальное пустое состояние; пустая неделя — отдельная подпись.
- Подпись источника: «таблица расписания воркера» или «график каталога», время МСК. Автоматизация
  обновления расписания и фоновые задачи не трогались.

## 3. Реальные API и данные

| Источник | Как используется |
|---|---|
| `lib/catalog` (`loadTitles`, `filterCatalog`, `homeRails`, `heroSlides`, `similarTitles`, `titleById`) | каталог, афиша, ленты, досье, похожее — серверный рендер, без клиентской фильтрации |
| `lib/schedule` (`getWeekSchedule`, `getDaySchedule`) | расписание и блок «Сегодня в эфире»; БД воркера или график каталога |
| `lib/schedule-core` (`weekBounds`, `mskDayIndex`) | даты, неделя, МСК |
| `lib/episodes` (`episodeInfo`, `cardEpisodeInfo`) | число серий в карточках и на странице |
| `lib/franchise.watchOrder` | лента «Франшиза» |
| `lib/aninova3/comics/source-links` (существующее) | блок первоисточников на странице аниме |
| `lib/library` + `/api/titles?slugs=` | «Продолжить просмотр» (локальная история, существующее) |
| `lib/aninova3/nav`, `schedule-view`, `clock` | новые тонкие слои представления, без данных |

Внешних запросов в рантайме нет: страницы читают локальные данные и (для расписания) ту же
серверную выборку, что и production-страница.

## 5. Адаптивность

Замеры на локальной production-сборке, 4 маршрута × 9 ширин (360, 390, 430, 768, 1024, 1280, 1440,
1920, 3840): **горизонтального переполнения 0 px**.

Сенсорные цели на 390 px: пункты нижней навигации, плитки дней, «Смотреть» — **0 элементов < 44 px**
(кнопка «Смотреть» была 30 px и получила `min-height/min-width: 44px`). На ТВ (`?tv=1`) цели
увеличиваются: день 85 px, «Смотреть» 56 px.

## 6. Доступность и контраст

| Элемент | Контраст | Требование |
|---|---|---|
| Время эфира / название | 17.32:1 | ≥ 4.5 |
| «Серия N», статус показа, подпись про МСК | 7.10:1 | ≥ 4.5 |
| Дата дня | 7.62:1 | ≥ 4.5 |
| Счётчик дня (активный, акцент) | 5.40:1 | ≥ 4.5 |
| Шапка, навигация | без изменений с B1-B (проверено в B1-C QA) | ≥ 4.5 |

- Статус показа передан подписью («вышла / сейчас / ожидается»), а не только цветом.
- Первый Tab — «К содержанию» с видимым `outline: 2px solid`; шапка достигается клавиатурой.
- Новые интерактивные элементы помечены `data-a3-focusable`, то есть входят в D-pad навигацию.
- У списка эфира семантический `<ol>`, у времени — `<time datetime>`; у навигации дней — `aria-label`
  и `aria-current`.
- `prefers-reduced-motion` отключает shimmer скелетона.

## 9. Что осталось незавершённым (по плану B2, не входит в B2-A)

1. **Группа 3** — страница серии и плеер в Nova Minimal: `A3Theatre` обёртка уже есть, но
   переработка кинозала — отдельный пакет; провайдеры и `PlayerShell` не трогались.
2. **Группа 4** — auth/profile: разделы навигации есть, миграция экранов не начиналась.
3. **Группа 5** — маршруты Comics в новом дизайне: каталог и страница уже реализованы в B1-E, но
   требуют B3 data contracts для полноценного переноса.
4. **Группа 6** — поиск/настройки/утилиты: глобальный поиск остаётся оверлеем (`/` и кнопка),
   отдельная страница результатов не начиналась.
5. «Скоро экранизации» из спецификации (§4.6) не создаётся: подтверждённых данных адаптаций в
   каталоге пока нет — страница без источника данных была бы фиктивной.
6. Светлая тема: не начиналась, тёмная остаётся единственной по решению владельца.

## 10. Безопасность

Production не затрагивался: нет деплоя, миграций, изменений Supabase/Redis/Vercel, DNS, секретов и
переменных окружения. `main` и предыдущие ветки не изменялись. PR и merge не выполнялись.
Ветка содержит только код preview-маршрутов, тесты, дизайн-скриншоты и этот отчёт.
