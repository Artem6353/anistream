# AniNova 3.0 — адаптивная спецификация B1-A

**Дата:** 2026-11-20
**Область:** три концепции прототипа, 10 экранов, ширины 390 / 768 / 1440 / 1920, две темы.
**Проверки:** `design-proto/scripts/screenshots.mjs`, результаты — `docs/design/b1/audit.json`.
**Скриншоты:** `docs/design/b1/screens/<concept>/<screen>-<width>[-light].jpg`

## 1. Брейкпоинты

| Точка | Смысл | Кто использует |
|---|---|---|
| `< 420` | узкий телефон (iPhone SE / 360–390) | A: компактные строки, скрытие правой меты |
| `< 600` | телефон | C: скрытие селектора озвучки в плеере |
| `≥ 600` | крупный телефон / планшет-портрет | B: 3 колонки в блоках; C: 2 колонки рейлов |
| `< 768` | мобильная раскладка | A/B: скрытие facet-года, мобильные отступы |
| `≥ 768` | планшет | A: сайдбар каталога, 3 карточки, шапка 64 px; B: двухколоночная сетка, индекс в 3 колонки |
| `≥ 900` | планшет-ландшафт / ноутбук | B: двухколоночный макет статьи и досье; C: включение desktop-навигации и отключение нижней панели |
| `≥ 1100` | ноутбук | B: индекс 36 / 1fr / 340 |
| `≥ 1200` | десктоп | A: 6 карточек, каталог 4 в сетке, 3 «продолжить»; C: 5 карточек, рейлы |
| `≥ 1600` | широкий десктоп | B: контейнер 1240 |
| `≥ 1700` | широкий десктоп | C: gutter 48, hero 82vh |
| `≥ 1800` | большой монитор | A: контейнер 1500, H1 56, gutter 40 |
| `1920` | ТВ/монитор | проверочная ширина для всех |

Брейкпоинты заданы в CSS каждой концепции; глобальные — только в `app/globals.css` (панель прототипа, читалка ≥900, индекс).

```css
/* Контейнеры */
A: --max: 1240px; → 1500px @1800;  gutter 20 / 28 / 32 / 40
B: --max: 1120px; → 1240px @1600;  gutter 20 / 32 / 40
C: --max: 1560px; gutter 18 / 32 / 48 @1700
```

## 2. Навигация

### A · Nova Minimal

| Ширина | Поведение |
|---|---|
| 390 | шапка 56 px: логотип, поиск, тема, бургер 44×44; навигация — drawer на всю высоту, строки 19 px с hairline, кнопки «Войти» / «Создать аккаунт» внизу; скролл body заблокирован, Esc закрывает, фокус возвращается на бургер |
| 768 | шапка 64 px, горизонтальная навигация, бургер скрыт, «Войти» появляется |
| 1440 | то же + поиск-панель под шапкой (результаты строками, 46 px) |
| 1920 | то же, контейнер 1500, навигация не растягивается на всю ширину |

### B · Nova Editorial

| Ширина | Поведение |
|---|---|
| 390 | мастохед в две строки: дата/номер, затем бренд 42 px и «Меню»; меню-обложка на всю высоту: номера 01–04, serif 26 px, крупные кнопки; поиск — отдельная панель под мастохедом |
| 768 | дата и номер в одну строку с брендом, рубрики появляются под мастохедом |
| 1440 | полный мастохед: дата слева, «Закрыть / Войти / Меню» справа, бренд 62 px, рубрики строкой |
| 1920 | контейнер 1240, мастохед не «плывёт», линейки на всю ширину контейнера |

### C · Nova Cinematic

| Ширина | Поведение |
|---|---|
| 390 | шапка 58 px (логотип, поиск, тема); **нижняя панель 58 px** с 4 пунктами, `padding-bottom: env(safe-area-inset-bottom)`; активный пункт — янтарная полоса сверху; контент получает нижний отступ |
| 600 | нижняя панель сохраняется, карточки 2 в ряд |
| 900 | нижняя панель скрывается, появляется горизонтальная навигация в шапке (логотип, ссылки, поиск, тема, вход) |

| 1920 | контейнер 1560, gutter 48, hero 82vh |

**Правило:** мобильная навигация не является «урезанной» — все 4 раздела и вход доступны; ни одна ссылка не спрятана только на мобильном.

## 7. Известные ограничения

1. **Нет focus trap в мобильном меню A/B.** Esc закрывает, фокус возвращается на кнопку, но Tab может уйти в контент под оверлеем. Исправление — в B1-B (общий `useFocusTrap`).
2. **Читалка не предзагружает следующую страницу.** На медленной сети возможен короткий «провал» при перелистывании. Решение: `<link rel="prefetch">` для `page+1`.
3. **Светлая тема C — вторичная.** Контраст проходит, но композиция hero рассчитана на тёмный фон; для production нужен отдельный art-direction светлого hero.
4. **1920 проверен на главной и плеере** (полные скриншоты) плюс превью в индексе. Остальные экраны на 1920 не сняты отдельно — сетка общая, но это стоит закрыть в B1-B.
5. **Планшет 1024 между 900 и 1100** не имеет отдельного скриншота; проверяется правилами 900/1100.
6. **Шрифты системные** — метрики отличаются между Windows/macOS, поэтому переносы и высоты строк в production нужно перепроверить после подключения webfont.
7. **Печатная версия** есть только как базовое правило (`@media print` скрывает панель прототипа); читалка комиксов не оптимизирована под печать.
8. **Плеер** — макет, не интеграция; поведение на реальном HLS-потоке не проверялось.

## 8. Как воспроизвести

```bash
cd design-proto
npm install
npm run build && npx next start -p 3518     # production-сборка
PROTO_BASE=http://localhost:3518 node scripts/screenshots.mjs        # экраны + состояния + audit
PROTO_BASE=http://localhost:3518 node scripts/screenshots.mjs --audit  # только проверки
PROTO_BASE=http://localhost:3518 node scripts/screenshots.mjs --states # только состояния
```

Скриншоты складываются в `docs/design/b1/`:

```
index-1440.jpg
screens/minimal/{home,catalog,anime,watch,comics,comic,read,profile,login,register}-{1440,390}.jpg
screens/minimal/{home,catalog,watch,read}-768.jpg, {home,watch}-1920.jpg

screens/minimal/state-{search-1440,menu-390,profile-tab-1440,saved-1440}.jpg
audit.json
```
