# AniNova 3.0 — B1-C: отчёт

## 1. Коротко

Связь «аниме ↔ первоисточник-комикс» реализована как **изолированный preview** в ветке
`design/aninova-3-b1-c-source-comics-2026-11` от коммита B1-B `8adbdd7` (`design/aninova-3-b1-b-hybrid-2026-11`).
Production не изменён, деплоя нет, Supabase/Redis/секреты/Vercel не затронуты, миграций нет.

Что появилось:

- типизированная модель связей (7 ролей) и устойчивые идентификаторы (`comic:anilist:<id>`);
- снимок relation-графа `lib/aninova3/comics/source-graph.json` + офлайн-скрипт его обновления;
- реестр комиксов, который собирает метаданные из графа и редакционные проверки из `source-data.ts`;
- двусторонний resolver без fuzzy-matching и без внешних запросов в рантайме;
- блок **«Первоисточник»** на странице аниме и блок **«Аниме-адаптации»** на странице Comics;
- публикационные ворота: `APPROVED` + проверенное RU-название + проверенные RU-метаданные + права + реальные RU-главы;
- 45 новых unit-тестов, 19 новых e2e (включая 9 проверок переполнения 360–3840), скриншоты и локальные замеры.

Главный честный результат: **реальная связь подтверждена ровно одна — «Наруто» (AniList 20 → MANGA 30011)**.
Она **не читается**: прав на публикацию и подтверждённых русских глав нет. Кнопка «Читать мангу» поэтому
не показывается, а карточка прямо говорит «первоисточник установлен, публикация пока недоступна».

## 2. Что именно сделано

### 2.1. Исследование (B1-C.0)

Проверено по факту, а не по названиям:

| Вопрос | Ответ |
|---|---|
| Что реально лежит в `Title.relations` | только `{ id, type }` и только для аниме-форматов |
| Типы relation в каталоге | `SEQUEL 2811`, `PREQUEL 2678`, `SIDE_STORY 2018`, `PARENT 1589`, `SPIN_OFF 455`, `SUMMARY 237` — **`ADAPTATION` отсутствует полностью** |
| Есть ли id первоисточника | нет: `source: MANGA` — тип, а не произведение |
| Сколько рёбер указывает на id вне каталога | 1987 рёбер / 1844 уникальных id, но их тип не сохранён → использовать нельзя |
| Есть ли метаданные манг | нет, каталог аниме-онли (`tv/movie/ona/ova/special`) |
| Что даёт `similarTitles`/`franchise.ts` | связи внутри аниме-каталога, для манги непригодны |
| Русские метаданные | сейчас: ручная редакционная запись (`source-data.ts`), кандидат на будущее — Shikimori manga API |

Вывод: **точную мангу из текущего `titles.json` получить невозможно** — это не «недостаточно данных»,
а структурная потеря `relationType`+типа узла при импорте. Поэтому появился отдельный снимок графа,
который снимается офлайн и коммитится, а рантайм ничего не запрашивает.

### 2.2. Модель (B1-C.1)

`lib/aninova3/comics/model.ts`:

- роли `SOURCE | ADAPTATION | SEQUEL | PREQUEL | SPIN_OFF | ALTERNATIVE | RELATED`;
- `ComicWork` (id, slug, RU/original название, вид, автор + флаг проверки, год, статус, обложка, главы, `externalIds`, `publication`, `provenance`);
- `invertRelation()` — `SOURCE→ADAPTATION`, `SEQUEL↔PREQUEL`, остальные симметричны;
- `RELATION_PRIORITY` — дедупликация одной и той же карточки из нескольких рёбер.

`lib/aninova3/comics/source-graph.ts`: маппинг сырых `relationType` → роль (`ADAPTATION→SOURCE`, `SIDE_STORY/SPIN_OFF→SPIN_OFF`, `PARENT/SUMMARY/OTHER/…→RELATED`, неизвестное → `UNKNOWN`/`RELATED`), `comicKindFrom(format, country)` (JP→манга, KR→манхва, CN/TW→маньхуа, ONE_SHOT→комикс, вебтун **не угадывается**), индексы `Map` по аниме/комиксу/AniList/MAL.

`lib/aninova3/comics/store.ts`: сборка `ComicWork` из графа + редакции, стабильные slug (транслит, коллизии → `-<anilistId>`), отчёт о дублях внешних id.

`lib/aninova3/comics/source-links.ts`: resolver в обе стороны, `skipped` с причинами (`comic_not_found`, `anime_not_found`, `ambiguous_external_id`).

### 2.3. Страница аниме (B1-C.2)

`/preview/aninova-3/anime/[slug]` → секция «Первоисточник» после сведений и серий, до «Похожего».

Карточка: оригинальная обложка, публичное название, вид, автор (только при подтверждении), год, доступные русские главы, статус, роль («Основной первоисточник» / «Также первоисточник» / продолжение / ответвление), честное состояние публикации и переход в Comics.

- если связей нет — секция не рендерится вообще (никаких «манга не найдена»);
- кнопка «Читать мангу» — только при `canOpenReader` (права + RU-главы + реальные страницы);
- если права есть, а страниц нет — так и написано: «страницы глав ещё не подключены»;
- демо B1-B в граф первоисточников не попадает.

### 2.4. Страница Comics (B1-C.3)

`/preview/aninova-3/comics/[slug]` → «Аниме-адаптации»: постер, русское название, тип, год, тип связи, переход в аниме. Секции нет, если связей нет. Ссылки получают стабильный `data-a3-key` (`anime:<id>`), поэтому пульт возвращает фокус на ту же карточку после «Назад».

Читалка (`/comics/[slug]/read`) открывается только для демо и для произведений с реальными разрешёнными страницами; для остальных — 404 без фиктивных глав.

### 2.5. Каталог Comics

Остался самостоятельным разделом: 8 демо-произведений с явной маркировкой «демо», RU-фильтр и правила публикации сохранены. Реальные первоисточники в публичный каталог не добавляются, пока не пройдут `APPROVED` (сейчас — 0).

## 4. Цепочка Naruto — где именно она останавливается

1. Метаданные Naruto найдены: AniList 20, slug `naruto`, `source: MANGA`, 220 серий;
2. `relations` содержат только аниме-связи (`SEQUEL`, `SIDE_STORY`, `SUMMARY`); id манги 30011 **в каталоге отсутствует**;
3. точный идентификатор взят из снимка relation-графа: `AniList 20 → ADAPTATION → 30011 (MANGA, MAL 11)`;
4. соответствующий `ComicWork` в реестре есть;
5. русское название «Наруто» и метаданные проверены редакционно (совпадает с проверенным RU-названием аниме);
6. **русских глав нет** (`chapters: []`);
7. **прав на публикацию нет** (`rightsVerified: false`, статус `PENDING_VERIFICATION`);
8. блок на странице Naruto появляется;
9. кнопки чтения нет — и это правильное поведение.

Остановка цепочки: **шаг 6–7 (публикация)**. UI это показывает честно, фиктивных глав нет.

## 6. Производительность по требованиям §9.1

- ни одного внешнего запроса в рантайме: снимок графа читается из файла один раз на процесс;
- нет N+1: разрешение — `Map.get` по `anilistId`, `comicId`, `malId`;
- полный каталог Comics на каждый рендер не грузится: реестр строится один раз и мемоизирован;
- тяжёлых вычислений в клиенте нет: новых клиентских компонентов ноль;
- в RSC-payload уходят только карточки связей (обложка/название/метаданные), без массивов глав;
- кэш Redis/Supabase не используется и не менялся.

## 7. Честные ограничения

1. **Снимок графа содержит одно ребро.** Полный проход по 8033 аниме требует разрешённого сетевого доступа к `graphql.anilist.co`; в этой сессии исходящие GraphQL-запросы были запрещены политикой окружения. Скрипт готов (`npm run graph:b1c`), данные — из одной зафиксированной записи.
2. **Права и главы не подключены ни у одного произведения.** Читаемых реальных комиксов — 0.
3. **Русские названия/авторы — ручная редакционная проверка одного произведения.** Автоматического источника RU-метаданных манги в проекте пока нет.
4. **Физический ТВ не тестировался** — только клавиатурная эмуляция Chromium.
5. **Git-worktree после переезда проекта**: служебные файлы worktree указывали на старые пути `C:/Users/artem/...`; операции Git в этом каталоге выполнялись через `--git-dir/--work-tree`. Владельцу нужно один раз выполнить `git worktree repair` (см. HANDOFF).
6. **Веб-шрифт/4K-ассеты** — как в B1-B, без изменений.
7. Для будущей полноценной системы нужен backend-контракт (описан, но не применён) и загрузка глав.

## 9. Что нужно от владельца

1. Разрешить однократный офлайн-проход `npm run graph:b1c` (AniList GraphQL, только чтение) — это наполнит граф реальными связями.
2. Дать решение по публикации: какие произведения и на каких основаниях получают `APPROVED` и русские главы.
3. Утвердить редакционные русские названия первоисточников (сейчас проверено одно — «Наруто»).
4. Подтвердить, что демо-раздел Comics остаётся демо до лицензий.

Подробности — в `ANINOVA_3_B1C_RELATION_MODEL.md`, `ANINOVA_3_B1C_SOURCE_MATCHING.md`,
