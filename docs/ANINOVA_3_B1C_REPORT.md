# AniNova 3.0 — B1-C: отчёт

## 1. Коротко

Связь «аниме ↔ первоисточник-комикс» реализована как **изолированный preview** в ветке
`design/aninova-3-b1-c-source-comics-2026-11`. Production не изменён, деплоя нет,
Supabase/Redis/секреты/Vercel не затронуты, миграций и изменений `PlayerShell`/провайдеров нет.

Что есть на конец этапа:

- **полный снимок relation-графа AniList**: 8033 запрошенных аниме → 8031 получено,
  **5748 рёбер**, **4100 произведений-комиксов**, 0 батчей с ошибкой;
- 7 ролей связи и устойчивые идентификаторы (`comic:anilist:<id>`), связь **только по точным id**;
- двусторонний resolver без fuzzy-matching, без внешних запросов в рантайме и без N+1;
- блок **«Первоисточник»** на странице аниме и блок **«Аниме-адаптации»** на странице Comics;
- многоисточниковые аниме (One Piece: манга + сборник + ваншот-прототип) и связи без
  первоисточника (секция называется «Связанные комиксы», а не «Первоисточник»);
- **слой кандидатов RU-метаданных**: 2198 произведений получили кандидата русского названия
  из Shikimori по MAL id с provenance; публично кандидат **не** показывается;
- три уровня достоверности (`UNVERIFIED → CANDIDATE → EDITORIALLY_VERIFIED`), отделённые от
  прав: наличие перевода или найденное название не считается подтверждением прав;
- публикационные ворота: `APPROVED` + проверенное RU-название + проверенные RU-метаданные +
  права + реальные RU-главы со страницами;
- 60 unit-тестов B1-C (было 45) и 22 e2e в профильном файле (было 18), включая переполнение
  360–3840, TV-навигацию, Escape-возврат фокуса и многоисточниковые страницы.

Главный честный результат: **5748 подтверждённых связей найдено, 0 произведений читается.**
Прав на публикацию нет ни у одного произведения, поэтому кнопки «Читать мангу» нет нигде,
а карточка прямо говорит «первоисточник установлен, публикация пока недоступна».

## 2. Что именно сделано

### 2.1. Исследование (B1-C.0)

Проверено по факту, а не по названиям:

| Вопрос | Ответ |
|---|---|
| Что реально лежит в `Title.relations` | только `{ id, type }` и только для аниме-форматов |
| Типы relation в каталоге | `SEQUEL 2811`, `PREQUEL 2678`, `SIDE_STORY 2018`, `PARENT 1589`, `SPIN_OFF 455`, `SUMMARY 237` — **`ADAPTATION` отсутствует полностью** |
| Есть ли id первоисточника | нет: `source: MANGA` — тип, а не произведение |
| Сколько рёбер указывает на id вне каталога | 1987 рёбер / 1844 уникальных id, тип не сохранён → использовать нельзя |
| Есть ли метаданные манг | нет, каталог аниме-онли (`tv/movie/ona/ova/special`) |
| Что даёт `similarTitles`/`franchise.ts` | связи внутри аниме-каталога, для манги непригодны |
| Русские метаданные | кандидаты — Shikimori manga API по MAL id; подтверждение — только редакционное |

Вывод: **точную мангу из текущего `titles.json` получить невозможно** — это структурная потеря
`relationType` и типа узла при импорте, а не «недостаточно данных». Поэтому граф снимается
отдельным офлайн-скриптом и коммитится, а рантайм ничего не запрашивает.

### 2.2. Снимок графа (`npm run graph:b1c`)

`scripts/aninova3-source-graph.mjs` → `lib/aninova3/comics/source-graph.json` (2.6 МБ).

- два прохода: `relations` по аниме-батчам (25 id) и `staff` только для собранных комиксов (топ-3 по релевантности);
- сохраняются **только** узлы формата `MANGA`/`ONE_SHOT`; аниме-рёбра и `MANGA/NOVEL` (ранобэ) отбрасываются;
- `429` с `Retry-After`, 5xx, таймауты и GraphQL-ошибки ретраятся с экспоненциальной паузой (до 60 с);
- батч, который так и не прошёл, **не теряется молча**: пишется `.cache/b1c/partial-graph.json`, снимок не перезаписывается, код выхода 1;
- запись атомарная (tmp + rename), предыдущий снимок уходит в `.cache/b1c/` с `.sha256`;
- `--verify`, `--dry-run`, `--ids=`, `--limit=`, `--batch=`, `--sleep=`, `--retries=`, `--timeout=`, `--staff-batch=`.

Фактический прогон (2026-11-22): 8033 запрошено, **8031 получено** (2 id — 2265 и 2268 — AniList
больше не отдаёт, они зафиксированы в `.cache/b1c/last-run.json`), 417 запросов, 13 ретраев
(все от `429`), **0 батчей с ошибкой**, 487 аниме без единого relation-ребра.

### 2.3. Модель (B1-C.1)

`lib/aninova3/comics/model.ts`:

- роли `SOURCE | ADAPTATION | SEQUEL | PREQUEL | SPIN_OFF | ALTERNATIVE | RELATED`;
- `ComicWork`: id, slug, **публичное** `titleRu` (пустое до проверки), `titleOriginal` (внутреннее),
  вид, автор + флаг проверки, год, статус, обложка, главы, `externalIds`, `publication`,
  `verification`, `titleRuCandidate`, `provenance`;
- `ComicVerification = 'UNVERIFIED' | 'CANDIDATE' | 'EDITORIALLY_VERIFIED'` — отдельно от прав;
- `PENDING_TITLE_TEXT = 'Информация о русскоязычном издании уточняется'`;
- `invertRelation()` — `SOURCE→ADAPTATION`, `SEQUEL↔PREQUEL`, остальные симметричны;
- `RELATION_PRIORITY` — дедупликация одной карточки из нескольких рёбер.

`lib/aninova3/comics/source-graph.ts`: маппинг `relationType → роль`
(`ADAPTATION→SOURCE`, `SIDE_STORY|SPIN_OFF→SPIN_OFF`, `PARENT|SUMMARY|OTHER|CHARACTER→RELATED`,
неизвестное → `RELATED` с сохранением сырого значения), `comicKindFrom(format, country)`
(JP→манга, KR→манхва, CN/TW→маньхуа, `ONE_SHOT`→комикс, вебтун **не угадывается**),
`Map`-индексы по аниме / комиксу / AniList / MAL / внутреннему id.

`lib/aninova3/comics/store.ts`: сборка `ComicWork` из графа + редакции + кандидатов,
стабильные slug (транслит, коллизии → `-<anilistId>`), отчёт о дублях внешних id.

`lib/aninova3/comics/source-links.ts`: resolver в обе стороны, `skipped` с причинами
(`comic_not_found`, `anime_not_found`, `ambiguous_external_id`), детерминированный порядок карточек
и один основной первоисточник (сериализованная манга приоритетнее ваншота).

### 2.4. Страница аниме (B1-C.2)

`/preview/aninova-3/anime/[slug]` → секция после сведений и серий, до «Похожего».

- нет рёбер — секции нет вообще (никаких «манга не найдена»);
- есть `SOURCE` — заголовок «Первоисточник»; только прочие роли — «Связанные комиксы»;
- карточка: обложка, публичное название (или нейтральная строка), вид, автор (только при
  подтверждении), год, статус, роль («Основной первоисточник» / «Также первоисточник» /
  продолжение / ответвление), доступные русские главы, честное состояние публикации, переход в Comics;
- несколько первоисточников — все карточки, но `is-primary` ровно у одной;
- кнопка «Читать мангу» — только при `canOpenReader` (права + RU-главы + реальные страницы);
- права есть, страниц нет — так и написано: «страницы глав ещё не подключены»;
- демо B1-B в граф первоисточников не попадает.

### 2.5. Страница Comics (B1-C.3)

`/preview/aninova-3/comics/[slug]` → «Аниме-адаптации»: постер, название, тип, год, роль связи,
переход в аниме. У манги «Наруто» их три (сериал, Shippuuden, фильм) — данные не подгоняются
под красивую единицу. Ссылки имеют стабильный `data-a3-key` (`anime:<id>`), поэтому пульт
возвращает фокус на ту же карточку после «Назад».

Читалка (`/comics/[slug]/read`) открывается только для демо и для произведений с реальными
разрешёнными страницами; для остальных — 404 без фиктивных глав.

### 2.6. Русские метаданные: кандидаты, а не проверка (`npm run ru:b1c`)

`scripts/aninova3-ru-metadata.mjs` → `lib/aninova3/comics/metadata-candidates.json` (внутренний),
`docs/data/aninova3-b1c-metadata-candidates.json` (полный отчёт),
`docs/data/aninova3-b1c-manual-review.json` (очередь ревью).

- источник — публичный Shikimori manga API **по MAL id** из снимка; поиск по названию связей не создаёт;
- проверка чужого id: ответ должен иметь тот же `id`, а `name` — пересекаться с оригинальным
  названием (иначе `NAME_MISMATCH`, кандидат не создаётся);
- прогресс в `.cache/b1c/ru-metadata-progress.json`, повторный запуск не тратит запросы;
- дополнительная сверка: Shikimori сам отдаёт `myanimelist_id` — он обязан совпасть (0 расхождений);
- из ответа берутся русское название, **официальное название русской лицензии** (`license_name_ru`),
  издатели/лицензиары, жанры, обложка, описание на русском, год, статус, тома и главы;
- результат по 2444 первоисточникам: **2198 CANDIDATE**, из них 184 с официальным RU-названием
  лицензии и 1458 с русским описанием; 5 `NOT_FOUND`, 174 без MAL id, 67 `NAME_MISMATCH`,
  0 `ID_MISMATCH`, 0 ошибок;
- `CANDIDATE` **не** включает ни `russianTitleVerified`, ни `rightsVerified`, ни показ в UI.

### 2.7. Публичное название (правило §9.2)

Русское название выводится только при редакционной проверке. Иначе — нейтральный текст
`PENDING_TITLE_TEXT`, а оригинальное название **не подставляется** вместо русского
(ни в заголовке карточки, ни в `<h1>` страницы комикса, ни в описании).
Внутренние поля (`titleOriginal`, `titleRuCandidate`) остаются для сопоставления и ревью.

## 6. Производительность по требованиям §9.1

- ни одного внешнего запроса в рантайме: снимок графа и кандидаты читаются из файла один раз на процесс;
- нет N+1: разрешение — `Map.get` по `anilistId` / `comicId` / `malId`;
- каталог Comics на каждый рендер не грузится: реестр строится один раз и мемоизирован;
- новых клиентских компонентов — ноль, весь блок серверный;
- в RSC-payload уходят только карточки связей, без массивов глав и без внутренних полей
  (`titleOriginal`, `titleRuCandidate`, provenance в разметку не попадают);
- Redis/Supabase не используются и не менялись.

## 7. Честные ограничения

1. **2 аниме из 8033 недоступны в AniList** (2265, 2268) — снимок честно фиксирует это в `meta.animeMissing`. Остальные 487 без рёбер — оригинальные работы, а не ошибка.
2. **Права и главы не подключены ни у одного произведения.** Читаемых реальных комиксов — 0.
3. **RU-названия: 1 проверено редакцией, 2198 — кандидаты.** Массовая автопромуция кандидатов в «проверенные» запрещена правилами этапа.
4. **Не все произведения покрыты кандидатами**: 174 без MAL id, 67 с несовпадением названия, 5 не найдены в Shikimori, 1930 вне SOURCE-набора.
   Даже 184 официальных RU-названия лицензии остаются кандидатами: наличие лицензии на издание не равно праву на перепубликацию в проекте.
5. **Физический ТВ не тестировался** — только клавиатурная эмуляция Chromium.
6. **Веб-шрифт/4K-ассеты** — как в B1-B, без изменений.
7. **Граф — снимок, а не живая связь.** Обновляется вручную (`npm run graph:b1c`), дата снимка видна в `meta.generatedAt`.
8. Для полноценной системы нужен backend-контракт (описан, не применён) и законная загрузка глав.
