## 1. Маршруты

| Маршрут | Что это |
|---|---|
| `/preview/aninova-3/auth` | реальный вход и регистрация; `?next=` — безопасный локальный путь |
| `/preview/aninova-3/profile` | реальный кабинет; только для серверной сессии |
| `/preview/aninova-3/profile/<username>` | публичный профиль на реальных публичных полях |
| `/auth/callback?next=/preview/...` | существующий callback; обменивает PKCE-код и возвращает в preview |
| `/auth`, `/profile`, `/profile/<username>` | production-маршруты; поведение по умолчанию сохранено |

Гость на `/preview/aninova-3/profile` уходит на
`/preview/aninova-3/auth?reason=protected&next=%2Fpreview%2Faninova-3%2Fprofile`.
После входа возвращается ровно на preview-профиль; production `/profile` в `next` не подставляется.

### 1.1. Безопасный возврат

- `lib/aninova3/preview-auth.ts` принимает только внутренний путь, начинающийся с `/`,
  отбрасывает `//host`, схемы, `\`, управляющие символы и внешние адреса.
- production `/profile` и `/auth` в preview-форме заменяются на preview-профиль,
  поэтому нельзя случайно вернуться в production или получить петлю входа.
- внешний `next` заменяется на `/preview/aninova-3/profile`.
- callback использует существующий `safeNextPath` и передаёт в preview только разрешённый
  локальный путь; OAuth allowlist и настройки Supabase не менялись.

## 2. Вход и регистрация

Страница `/preview/aninova-3/auth` использует существующий `AuthPageClient` и существующие
Supabase browser/server clients. Демо-компонент `A3Auth` не используется как реальный вход.

| Сценарий | Поведение |
|---|---|
| Вход по email и паролю | `signInWithPassword`, понятная ошибка Supabase, форма остаётся на месте |
| Регистрация | `signUp` с username в metadata; письмо подтверждения, без фиктивного входа |
| Ошибки полей | email, пароль и username проверяются до запроса; `aria-invalid`, `aria-describedby` |
| Загрузка | кнопка блокируется, показывает spinner и не отправляет форму повторно |
| Подтверждение email | честный экран «Проверьте почту»; ссылка ведёт через существующий callback |
| Google OAuth | существующий `signInWithOAuth`; возврат через `/auth/callback?next=...` |
| Отказ/ошибка OAuth | ошибка показывается в preview-оболочке, есть повтор входа |
| Уже вошёл | auth сразу возвращает в безопасный `next` (по умолчанию preview-профиль) |
| Supabase не настроен | H2 «Вход пока не настроен», без полей и без фальшивой сессии |
| Тема | preview принудительно тёмный, включая первый кадр до гидратации |
| Мобильный экран | форма входа целиком помещается в первый экран 390×844; преимущества скрыты, каталог доступен из шапки |

### 2.1. Callback и сессия

`AuthCallbackPageClient` — единственный владелец обмена PKCE-кода. В `lib/supabase/browser.ts`
отключён автоматический `detectSessionInUrl`: SDK больше не пытается обменять код раньше
страницы и не «съедает» `code_verifier`. Это исправило реальный Google-вход, который до фикса
падал с «Потерян code_verifier» после успешного ответа провайдера.

Сессия, как и раньше, зеркалируется в legacy-хранилище через `mirrorSessionToLegacy`;
`notifyAuthChange()` обновляет шапку без перезагрузки. Callback поддерживает и старый
hash-путь с `access_token`/`refresh_token`.

В `lib/supabase/env.ts` значения читаются прямыми обращениями к `process.env.NEXT_PUBLIC_*`,
чтобы Next подставил их в клиентский бандл. Динамический `process.env[key]` в браузере пуст
и раньше приводил к ложному «вход не настроен» при настроенной сборке.

## 3. Кабинет

`/preview/aninova-3/profile` — серверная страница. Она проверяет `getServerUser()` и только
потом загружает `loadProfileBundle`. Гость не получает ни имени, ни статистики, ни списков:
сначала редирект на preview-auth.

Переиспользованы без второй реализации:

- `getServerUser()` и `loadProfileBundle`;
- `ProfileDashboard`;
- `AccountSettings`;
- `SignOutButton`;
- существующие проверки владения и RLS-чтение.

Сохранены и проверены:

| Блок | Что видно |
|---|---|
| Шапка | аватар, имя/ник, email, дата регистрации, счётчики часов/серий/тайтлов/стриков |
| Обзор | AniDNA, архетип, жанры, часы, серии, стрик, «Из чего собрано», скачивание PNG |
| Мои списки | реальные строки, пустые состояния, preview-ссылки на аниме |
| История | реальные просмотры, пустые состояния, preview-ссылки |
| Настройки | ник, био, счётчик символов, аватар (PNG/JPEG/WebP до 2 МБ), сохранение, ошибки |
| Тема | в preview только «Тёмная» с пояснением; production по-прежнему dark/light/system |
| Выход | `/api/auth/signout`, очистка legacy-сессии, возврат на preview-главную |
| Ошибка загрузки | `app/preview/aninova-3/profile/error.tsx` — честный экран и повтор |

Ссылки внутри кабинета ведут в preview: каталог, аниме, публичный профиль, списки,
история, настройки. Кнопка выхода ведёт на `/preview/aninova-3/`, а не в production.

## 4. Публичный профиль

`/preview/aninova-3/profile/<username>` использует новый серверный загрузчик
`lib/aninova3/public-profile.ts`: анонимный Supabase-клиент, только публичные поля
`username`, `avatar_url`, `banner_url`, `bio`, `pinned_achievements` и счётчики подписок.
Email, списки, история, прогресс и приватные таблицы туда не запрашиваются.

- Существующий пользователь: шапка, аватар/баннер, био, закреплённые достижения, подписчики/подписки.
- Свой профиль определяется на сервере через `getServerUser()`: кнопки «Подписаться» и
  «Написать сообщение» не показываются.
- Чужой профиль: существующие `FollowButton` и `WriteDmButton`; подписка работает через
  существующий механизм и реальные данные.
- Несуществующий пользователь: `notFound()`, честная preview-404, без пустого макета.
- Секция «Приватность» прямо объясняет, что списки и история остаются личными.
- Никаких новых RLS-политик, API и расширения доступа нет.

### 4.1. Ограничение сообщений

Раздел `/messages` не входит в B2-C и в preview не портирован. Чтобы кнопка «Написать
сообщение» не уводила из прототипа в production, `WriteDmButton` получил preview-режим:
он показывает честный тост «Сообщения появятся в одном из следующих этапов» и остаётся
на публичном профиле. Production-поведение по умолчанию не изменилось.

## 5. Долги B2-B

### 5.1. Оригинальное название

Публичный `title.romaji` убран со страницы preview-аниме и из всей публичной preview-разметки:

- нет `.a3-anime__orig` и romaji в HTML, `<title>`, SEO-мета, обложке, `alt` и `aria`;
- инициалы `PosterArt` берутся из русского названия, при его отсутствии — нейтральный `?`;
- внутреннее сопоставление тайтлов не менялось.

E2E проверяет чужое оригинальное название во всех перечисленных местах и отдельно — инициалы
«ОП»/«АТ» из русского названия при заблокированных изображениях.

### 5.2. Клавиша N

В `components/aninova3/A3Theatre.tsx` глобальный `N` больше не срабатывает вне сцены:

- `N` внутри сцены/контролов ведёт на следующую серию preview;
- вне сцены, в шапке, навигации и других областях — игнорируется;
- в `INPUT`, `TEXTAREA`, `SELECT`, `contenteditable` печатается как обычный символ;
- в диалоге жалобы и других `dialog`/`aria-modal` не переключает серию;
- при `repeat` и без следующей серии ничего не делает;
- обработчик стоит в capture-фазе и гасит глобальный `N` `PlayerShell` вне сцены, поэтому
  нет двойной обработки и ухода в production `/anime/...`.

`PlayerShell`, видео, HLS, провайдеры, автоплей, сохранение позиции и жалобы не менялись.

## 6. Визуал и адаптивность

Nova Minimal, только тёмная тема: графитовые поверхности, тонкие линии, спокойный индиго
`--a3-accent`, ясные формы и карточки, без стеклянных слоёв, декоративных градиентов и
анимационных эффектов. Кабинет выглядит как настоящий дашборд, а не статичный макет.

- 360, 390, 430, 768, 1024, 1280, 1440, 1920, 3840 px: горизонтального переполнения нет
  (auth и guest-профиль проверены E2E; кабинет — скриншотами 390/1440/1920 и ручной проверкой).
- На 390 px форма входа целиком в первом экране, фиксированная нижняя навигация не закрывает
  кнопку «Войти»; на 360/430 переполнения нет.
- Мобильные табы кабинета — сетка 2×2, нижний отступ 92 px, контент не прячется за навигацией.
- TV 1920: safe-area, крупные цели, `data-tv`, форма и кабинет не растягиваются на всю ширину.
- `prefers-reduced-motion` отключает переходы auth и кабинета.
- Контраст (WCAG AA): текст/фон 17.32:1, muted/поверхность 6.61:1, белый/кнопка 4.62:1,
  danger/поверхность 8.02:1, focus/фон 8.17:1; индиго-текст на фоне 5.03:1.
- Клавиатура: поля и кнопки доступны по Tab, видимый focus-ring 2 px; ошибки связаны
  с полями через `aria-describedby`; заголовки и форма имеют корректную иерархию h1/h2.

Скриншоты: `docs/design/b2c/screens/` — auth 390 и 1440, profile 390 и 1440, public 1440,
TV 1920. Мобильные снимки сделаны во вьюпорте, поэтому фиксированная навигация показана
на своём реальном месте, а не посреди длинной страницы.

`SignOutButton`, `WriteDmButton`. `lib/supabase/browser.ts` и `lib/supabase/env.ts`
исправляют реальные ошибки входа и не меняют контракт сессии.

## 9. Ограничения

1. Сообщения (`/messages`) не портированы; в preview кнопка DM показывает честный тост и не уходит в production.
2. Кнопка «Подписаться» гостю открывает существующий `AuthModal` (production-компонент), а не preview-страницу входа; после входа подписка работает на реальных данных. Стилизация модалки — отдельная задача.
3. Реальный Google-провайдер в тестах не вызывается: проверен существующий механизм и его контракт на mock (успех и отказ).
4. Письмо подтверждения зависит от шаблона Supabase и allowlist; они не менялись, тест проверяет переход и экран ожидания.
5. Preview зафиксирован в тёмной теме; светлая тема ждёт решения владельца.
6. Проверки Supabase/Redis/Vercel выполнялись на изолированном mock и локальной сборке, не на боевых сервисах.
