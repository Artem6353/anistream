## 1. Цель этапа

Собрать проверяемый локально гибрид утверждённых концептов A и C, подготовить его к будущей интеграции и не переносить ничего в production до отдельного решения владельца.

Утверждено и не обсуждается в B1-B:

- тёмная тема как единственная для публичного интерфейса;
- индиго — единственный брендовый акцент;
- TV-first: полноценное управление стрелками, Enter и Escape;
- плотный каталог, а не редакционный журнал;
- кинематографичная сцена плеера из C, но без переписывания плеера;
- отдельный каталог комиксов, только RU, с честной демо-маркировкой;
- реальные постеры каталога, без нарисованных заглушек;
- производительность важнее эффектов: без glassmorphism, тяжёлых теней и неона;
- системный шрифт по умолчанию, без загрузки веб-шрифта;
- автоматические TV-тесты обязательны; отсутствие физического ТВ нельзя замалчивать.

## 3. Изоляция от production

1. Все новые маршруты живут только в `app/preview/aninova-3/**`.
2. Включение — переменная окружения `ANINOVA3_PREVIEW=1|true|on`.
3. Без флага layout preview вызывает `notFound()` → 404, а не «пустую» страницу.
4. `export const dynamic = 'force-dynamic'` — флаг проверяется на каждом запросе, одна сборка работает в обоих режимах.
5. `components/system/ChromeGate.tsx` скрывает production-шапку, футер, мобильную навигацию, cookie-баннер и auth-gate только на `/preview/aninova-3`.
6. `MainGate` заменяет корневой `<main>` на `<div>` внутри preview, чтобы на документе был ровно один `<main>` (его даёт `A3Shell`). Вне preview разметка не меняется.
7. В preview не импортируются Supabase, Redis, платёжные и серверные секреты. Авторизация — демонстрационная форма без отправки.
8. Метаданные preview: `robots: noindex, nofollow`.
9. Production-маршруты, API и база не изменяются; проверено сборкой и запросами к `/` и `/preview/aninova-3` с флагом и без.

## 5. Данные и честная маркировка

- Аниме-каталог, постеры, баннеры, серии, похожие тайтлы — из текущего каталога приложения.
- Комиксы — **вымышленные демо-произведения**; на главной Comics, в карточках, на странице комикса и в читалке стоит маркировка «демо» / «демонстрационные страницы».
- Изображения страниц комикса — сгенерированные демо-страницы, не главы из каталога.
- Профиль, история, закладки, прогресс — локальные демо-состояния (`localStorage`/`sessionStorage`), не аккаунт Supabase.
- Формы входа и регистрации показывают валидацию и состояния, но **не отправляют** данные.
- Плеер использует настоящий `PlayerShell`: если у серии нет источника, он честно показывает пустое состояние; постерный слой не имитирует воспроизведение.

## 8. Риски и их снижение

| Риск | Снижение |
|---|---|
| Случайное влияние на production | отдельные маршруты + флаг + `force-dynamic`; production-компоненты не переписаны |
| Плеер сломается при обёртке | `A3Theatre` передаёт те же props в существующий `PlayerShell`, логика HLS/провайдеров не менялась |
| D-pad застревает на нативных контролах | фасеты каталога сделаны ссылками-чипами вместо `<select>`; поиск — отдельный оверлей |
| Фокус «уезжает» после возврата | стабильные id на основе href/класса, а не индекса в DOM |
| Демо-данные примут за реальные | маркировка «демо» на всех уровнях Comics, формы без отправки, отчёт фиксирует ограничения |
| TV-поведение проверено только эмуляцией | в отчёте и QA явно указано: физический ТВ/пульт не тестировались |

## 9. Что дальше (после решения владельца)

1. Выбрать: оставить preview как есть, доработать отдельные блоки или начать интеграцию.
2. Зафиксировать реальные источники для кинозала и проверить HLS на целевом ТВ.
3. Решить судьбу Comics: демо-каталог, реальные лицензии или скрыть раздел.
4. Подключить реальную авторизацию вместо демо-формы.
5. Проверить на физическом ТВ и пульте (фокус, скорость, overscan, back-кнопка).
6. Только затем — перенос в production отдельным PR.
