# ЧАСТЬ I. B1-D.2

## 1.1. Исправленные остатки

1. **Подпись «· оригинал аниме» убрана.** В `A3SourceCard` она добавлялась к статусу
   произведения при `role === 'SOURCE' && directionConfirmed` — то есть подтверждённому
   первоисточнику приписывала «оригинал аниме», что противоречит самой роли. Подпись
   удалена целиком: роль карточки («Основной первоисточник», «Комикс по аниме», …) уже
   говорит то же самое, дублирование только путало.
2. **«Первоисточник установлен, публикация пока недоступна» — только при подтверждении.**
   Фраза и ссылка «О первоисточнике» теперь требуют одновременно `role === 'SOURCE'` и
   `confidence === 'confirmed'`. Раньше достаточно было подтверждения направления, и у
   карточки «Комикс по аниме» появлялся текст про установленный первоисточник.
3. **Описание секции зависит от фактического основания (`basis`), а не от флага уровня.**
   Раньше все предположительные связи объяснялись «определено по годам выпуска» — но
   `inferred` бывает и тогда, когда каталог знает первоисточник, а у комикса нет года
   (`catalog-manga`). Теперь:

| Состояние | Основание | Текст описания |
|---|---|---|
| подтверждено | `catalog-manga` | «Оригинальное произведение, по которому снято аниме…» |
| подтверждено | `catalog-original` | «Это оригинальное аниме, поэтому комикс создан по нему…» |
| вероятно | `dates` | «…направление определено по годам выпуска и требует проверки» |
| вероятно | `catalog-manga` | «Каталог сообщает, что аниме снято по манге, но год выпуска комикса не подтверждён…» |
| вероятно | смешанные | «Направление определено косвенно и требует проверки» |
| неизвестно | `catalog-conflict` | «…данные каталога и годы выпуска противоречат друг другу» |
| неизвестно | `catalog-other-medium` | «Аниме снято по другому первоисточнику, поэтому роль этого комикса не установлена» |
| неизвестно | `none` | «…данных для определения направления недостаточно» |
| нет первоисточника | — | «Комиксы, подтверждённые по идентификатору AniList…» |
| только комиксы по аниме | `catalog-original` | «Оригинальное аниме: комиксы созданы по нему…» |

Заголовок и описание вынесены в модель (`sourceSectionTitle`, `sourceSectionDescription`),
поэтому проверяются юнит-тестами, а не только глазами в браузере.

## 1.2. Новые тесты B1-D.2 (7)

- подтверждённый комикс-первоисточник не подписывается как «оригинал аниме»;
- подтверждённое оригинальное аниме объясняется отдельным текстом;
- предположительная связь по датам объясняется годами выпуска;
- предположительная связь из каталога без года **не** описывается как сравнение дат;
- неизвестное направление не получает утверждающей подписи (все три основания);
- описание противоречия отличается от описания нехватки данных;
- обе стороны связи описывают подтверждённый первоисточник согласованно.

## 3. Массовая сверка русских метаданных (все 2444, не выборка)

Скрипт `scripts/aninova3-b1e-metadata-verify.mjs` (`npm run ru:verify`), источник —
Shikimori по MAL id из графа. Для каждого произведения проверены:

1. AniList id из графа ↔ произведение в реестре;
2. MAL id из графа ↔ запрошенный MAL id;
3. Shikimori `id` = MAL id и `myanimelist_id` = MAL id;
4. принадлежность русского названия произведению (sanity-check по названию, связь при этом
   строится только по id);
5. качество русского текста: кириллица, отсутствие HTML/разметки/заглушек, длина, доля латиницы;
6. дубликаты названий у разных произведений;
7. ссылка на источник и дата проверки сохранены для каждой записи;
8. лицензионное название помечено как заявка источника, а не как подтверждение издателя.

Проход выполнен **по живым ответам**: 2444 произведения, 2285 запросов, 0 ошибок, 0 ответов
429 (rate-limit не потребовался при 1.5 запроса/с), checkpoint возобновляем.

## 6. Нейтральные слаги

| Статус названия | Слаг | Пример |
|---|---|---|
| проверено (`SOURCE_VERIFIED` / `EDITORIALLY_VERIFIED`) | транслит русского названия | `/comics/razyskivajutsja` |
| не проверено | `comic-<anilistId>` | `/comics/comic-30025` |

- оригинальное иностранное название в адресе не используется;
- слаг уникален (коллизии разрешаются суффиксом `-<anilistId>`);
- слаг стабилен: зависит от проверенного названия и AniList id, а не от порядка обработки;
- старые ссылки, построенные из оригинального названия, разрешаются через внутренний
  legacy-индекс и перенаправляются на канонический адрес (307), сам слаг в адресной строке
  не остаётся;
- страницы непроверенных произведений не раскрывают оригинальное название ни в `<h1>`,
  ни в `<title>`, ни в хлебных крошках, ни в адресе.

## 7. Подготовка к главам (без подключения глав)

Контракт зафиксирован в модели (`ComicChapter`): `source` (`licensed-publisher` /
`authorized-partner` / `editorial-demo`), `rightsVerifiedAt`, `availability`
(`public` / `hidden`), `updatedAt`, `pages`, `pageImages`. Скрытая глава не попадает в
публичную читалку даже при наличии страниц; прямые URL глав без прав отдают 404.

Схема для переноса в БД — **проект, не применён** (локальная спецификация):

```
comic_work(id, anilist_id, mal_id, shikimori_id, slug, kind, year, status,
           verification, metadata_source_url, metadata_checked_at, license_name_ru,
           license_claim_source, official_publisher_confirmed)
comic_work_title(comic_id, locale, title, source, status, checked_at)   -- ru/en/ja
comic_work_genre(comic_id, genre)
comic_work_anime(comic_id, anime_anilist_id, role, direction, confidence, basis)
comic_chapter(id, comic_id, number, language, title, pages, source, availability,
              rights_verified_at, updated_at)
comic_chapter_page(chapter_id, page_no, url, width, height)
comic_chapter_log(chapter_id, changed_at, actor, field, from_value, to_value)
```
