## 3. Что нужно от владельца

### 3.1. Починить worktree после переезда проекта

Проект переехал в `D:/ПРОЕКТ AniNova`, но служебные файлы worktree остались от
`C:/Users/artem/...`. В прошлой сессии `git worktree repair` был запрещён политикой окружения,
поэтому операции выполнялись через `--git-dir/--work-tree`; в этой сессии repair выполнен и все
пять worktree снова резолвятся по путям `D:`. Если после новых переездов `git status` снова
начнёт ругаться:

```powershell
cd "D:\ПРОЕКТ AniNova\anistream"
git worktree repair `
  "D:/ПРОЕКТ AniNova/anistream-b1b" `
  "D:/ПРОЕКТ AniNova/anistream-b1c" `
  "D:/ПРОЕКТ AniNova/anistream-design" `
  "D:/ПРОЕКТ AniNova/anistream-perf"
git worktree list
```

### 3.2. Пройти очередь русских названий

4099 произведений показывают нейтральный текст «Информация о русскоязычном издании уточняется»,
потому что их русское название не сверено. Очередь отсортирована по влиянию:

```bash
docs/data/aninova3-b1c-manual-review.json   # очередь + проблемы (name/id mismatch, not found)
```

Подтверждение вносится в `lib/aninova3/comics/source-data.ts`:
`russianTitleVerified: true`, `metadataVerified`, `verifiedAt`, `verificationBasis`. Автоматически
найденное название проверенным не считается — это правило этапа, а не недоработка.

### 3.3. Утвердить публикационную политику

`rightsVerified: false` у всех, значит читаемых произведений 0. Нужно решение:

- какие произведения получают `APPROVED` и на каком основании;
- где хранятся подтверждения (в проекте — только флаги и даты, без внутренних документов в публичных полях);
- кто и как проставляет русские главы со страницами.

### 3.4. Обновлять снимок графа

Снимок — датированный, а не живой. Обновление (только чтение AniList, ~7 минут):

```bash
cd "D:/ПРОЕКТ AniNova/anistream-b1c"
npm run graph:b1c -- --dry-run --ids=20,21   # проверка механики
npm run graph:b1c -- --verify                # перепроверить текущий снимок
npm run graph:b1c                            # полный проход
npm run ru:b1c                               # добрать кандидатов RU (кэш не даёт повторных запросов)
npm run report:b1c                           # пересчитать отчёт и инварианты
```

Для нового произведения (например только что вышедшего аниме) достаточно `--ids=<anilistId>`.
Батч, который не прошёл, не портит снимок: пишется `.cache/b1c/partial-graph.json`, код выхода 1.

## 6. Границы, которые нельзя нарушать дальше

1. Не связывать произведения по названию — только по id (`anilist`, `mal`, внутренний).
2. Не подставлять иностранные главы, не генерировать отсутствующие, не выдавать демо за реальный контент.
3. Не ставить `rightsVerified: true` без основания; наличие перевода ≠ права.
4. Не показывать публично внутренние документы и детали лицензий.
5. Не выводить иностранное название вместо непроверенного русского — только нейтральный текст.
6. Не переписывать `PlayerShell` и провайдеры в рамках связей аниме↔Comics.
7. Не делать N+1 внешних запросов: любая новая связь — индексированный доступ к снимку/БД.
