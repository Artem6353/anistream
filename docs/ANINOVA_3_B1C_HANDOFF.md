## 2. Что нужно сделать первым делом (владелец)

### 2.1. Починить worktree после переезда проекта

Проект переехал в `D:/ПРОЕКТ AniNova`, но служебные файлы worktree остались от
`C:/Users/artem/...`. В этой сессии изменение git-метаданных было запрещено политикой
окружения, поэтому операции выполнялись через `--git-dir/--work-tree`. Один раз выполнить:

```powershell
cd "D:\ПРОЕКТ AniNova\anistream"
git worktree repair `
  "D:/ПРОЕКТ AniNova/anistream-b1b" `
  "D:/ПРОЕКТ AniNova/anistream-b1c" `
  "D:/ПРОЕКТ AniNova/anistream-design" `
  "D:/ПРОЕКТ AniNova/anistream-perf"
git worktree list
```

После этого `git status` в worktree заработает штатно. Файл-артефакт `.pi-write-probe.txt`
в корне `anistream-b1c` — служебный след проверки доступа к каталогу, его можно удалить.

### 2.2. Разрешить однократный проход по AniList

Полный снимок графа не снят: исходящие GraphQL-запросы в этой сессии были запрещены. Разрешить
запуск (только чтение, без записи в БД/Redis):

```bash

npm run graph:b1c -- --ids=20,21 --dry-run   # проверка механики
npm run graph:b1c -- --verify                # перепроверить текущий снимок (Naruto)
```

После прохода стоит ожидать сотни связей вместо одной. **Обязательно** просмотреть отчёт:
рёбра со `skipped` и причиной `ambiguous_external_id` — кандидаты на ручной разбор.

### 2.3. Утвердить публикационную политику

Сейчас `rightsVerified: false` у всех, значит читаемых произведений 0. Нужно решение:

- кто и как проставляет русские названия/авторов (редакционная запись в `source-data.ts`).

## 5. Границы, которые нельзя нарушать дальше

1. Не связывать произведения по названию — только по id.
2. Не подставлять иностранные главы, не генерировать отсутствующие, не выдавать демо за реальный контент.
3. Не ставить `rightsVerified: true` без основания; наличие перевода ≠ права.
4. Не показывать публично внутренние документы и детали лицензий.
5. Не переписывать `PlayerShell` и провайдеры в рамках связей аниме↔Comics.
6. Не делать N+1 внешних запросов: любая новая связь — индексированный доступ к подготовленному снимку/БД.

## 6. Известные ограничения текущего среза

- `webtoon` как вид в данных не встречается (AniList не даёт отдельного формата) — выставляется только редакционно;
- Shikimori id в модели зарезервирован, но не заполняется;
