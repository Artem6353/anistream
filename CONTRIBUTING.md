# Регламент ветвления (ТЗ, раздел 6)

- `main` — продакшен: деплой автоматически при мерже (Vercel/Oracle).
- `dev` — staging: превью-деплой, сюда собираются все фичи.
- `feature/*` — разработка задач спринтов (`feature/player-epbar`, `feature/reviews`…).

## Правила Pull Request

1. PR из `feature/*` в `dev`, после проверки — `dev` → `main`.
2. Обязательное код-ревью минимум одним участником перед мержем в `main`.
3. CI должен быть зелёным: `typecheck`, `build`, `smoke` (`.github/workflows/ci.yml`).
4. Коммиты атомарные, сообщение: `тип(область): описание` (`fix(player): …`, `feat(social): …`).
5. Автодобавление контента не коммитится вручную: `sync-catalog.yml` (каждые 6 ч) пушит
   `lib/data/titles.json`; спорные тайтлы модератор правит через админку/PR.
